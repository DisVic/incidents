# ДЕТАЛЬНОЕ ОПИСАНИЕ ФУНКЦИОНАЛА СИСТЕМЫ
## Корпораторативная система управления инцидентами

---

## 1. АВТОРИЗАЦИЯ И УПРАВЛЕНИЕ ПОЛЬЗОВАТЕЛЯМИ

### 1.1. Вход в систему
- Форма логина: email + пароль
- JWT-токены: access_token (15 мин) + refresh_token (7 дней)
- Автоматический выход при истечении токена

### 1.2. Восстановление пароля
- Форма "Забыли пароль" — ввод email
- Генерация токена сброса (действителен 1 час)
- Отправка письма со ссылкой на сброс пароля
- Форма сброса пароля по токену

### 1.3. Смена пароля
- В профиле: текущий пароль + новый пароль
- Email-уведомление о смене пароля

### 1.4. Роли пользователей
| Роль | Права доступа |
|------|---------------|
| Admin | Полный доступ ко всем функциям |
| Manager | Управление инцидентами своего отдела, просмотр статистики |
| Executor | Работа с инцидентами своего отдела (взятие в работу, решение) |
| User | Создание инцидентов, просмотр своих инцидентов |

### 1.5. Управление пользователями (Admin)
- Список пользователей с пагинацией
- Создание пользователя: email, ФИО, роль, отдел, пароль
- Редактирование: ФИО, роль, отдел, телефон
- Блокировка/разблокировка (is_active)
- Удаление (кроме последнего Admin)
- При блокировке исполнителя — его инциденты сбрасываются в статус "Новый"

### 1.6. Профиль пользователя
- Просмотр своих данных
- Редактирование: ФИО, телефон
- Смена пароля
- Загрузка аватара (Base64, до 500KB)

### 1.7. Управление отделами (Admin)
- Список отделов
- Создание/редактирование: название, описание, руководитель
- Удаление (если нет пользователей)

## 2. УПРАВЛЕНИЕ ИНЦИДЕНТАМИ

### 2.1. Создание инцидента
**Доступ:** Все роли

**Поля формы:**
- Заголовок (5-255 символов)
- Описание (минимум 10 символов)
- Категория (выпадающий список)
- Приоритет (Низкий/Средний/Высокий/Критический)
- Отдел-исполнитель (выпадающий список)

**Автоматически при создании:**
- Статус: "Новый"
- Дата создания
- Инициатор (текущий пользователь)
- Дедлайн SLA (расчёт по SLA-политике)
- Запись в истории: "Инцидент создан"
- Уведомления: Manager отдела, Admin, Executor'ы отдела

### 2.2. Список инцидентов
**Колонки таблицы:**
- ID, Заголовок, Категория, Приоритет, Статус, Отдел, Инициатор, Исполнитель, Дата создания, Дедлайн SLA

**Фильтры:**
- По статусу (множественный выбор)
- По приоритету
- По категории
- По отделу
- По статусу SLA: просроченные / близкие к дедлайну (>80%) / в норме
- Поиск по заголовку

**Сортировка:**
- По дате создания, дедлайну, приоритету, заголовку

**Пагинация:** 20/50/100 записей

**Права видимости:**
- User: только свои инциденты
- Executor: инциденты своего отдела + созданные им
- Manager: инциденты своего отдела (или все для Admin)
- Admin: все инциденты

### 2.3. Детальная страница инцидента

**Блоки информации:**
1. **Основная информация:** ID, статус, приоритет, категория, отдел, заголовок, описание, инициатор, исполнитель, даты (создания, назначения, взятия в работу, решения, закрытия), SLA-дедлайн, индикатор просрочки
2. **Комментарии:** список комментариев с автором и датой, форма добавления
3. **История изменений:** таймлайн всех изменений статуса, назначения, приоритета
4. **Действия:** зависят от роли и статуса

**Доступные действия:**
- Взять в работу (Executor, Manager, Admin) — если статус "Новый"/"Назначен" и нет исполнителя
- Назначить исполнителя (Manager, Admin) — выбор из сотрудников отдела
- Изменить статус — с обязательным комментарием
- Изменить приоритет — с пересчётом дедлайна
- Отметить как решённый (Executor) — с комментарием
- Закрыть инцидент (User/Manager/Admin) — только если статус "Решён"

### 2.4. Статусы инцидентов
| Статус | Описание |
|--------|----------|
| Новый | Создан, ожидает назначения |
| Назначен | Назначен конкретный исполнитель |
| В работе | Исполнитель работает над решением |
| Решён | Решён исполнителем, ожидает закрытия |
| Закрыт | Закрыт инициатором, работа завершена |

### 2.5. Категории (настраиваемые Admin'ом)
- По умолчанию: Сеть, Оборудование, ПО, Доступ, Прочее
- CRUD-операции в настройках

## 3. SLA И ЭСКАЛАЦИЯ

### 3.1. SLA-политики
**Настройка (Admin):**
- Время на решение для каждого приоритета
- По умолчанию:
  - Критический: 4 часа
  - Высокий: 8 часов
  - Средний: 24 часа
  - Низкий: 72 часа

**Расчёт дедлайна:**
- Рабочие часы: 9:00-18:00, Пн-Пт
- Выходные и праздники не учитываются
- При создании инцидента дедлайн = время создания + SLA-часы (с учётом рабочих часов)

### 3.2. Мониторинг SLA
**Фоновая задача (Celery, каждые 5 минут):**
- Проверка активных инцидентов (Новый, Назначен, В работе)
- При превышении дедлайна: флаг overdue = True
- Отправка уведомлений о просрочке

**Визуальная индикация:**
- Зелёный: осталось > 40% времени
- Жёлтый: осталось 10-40%
- Красный: осталось < 10%
- Красный с текстом "ПРОСРОЧЕН": дедлайн истёк

### 3.3. Эскалация
**Уровень 1 (80% SLA):**
- Уведомление Manager'ам отдела и Admin'ам
- Триггер: использовано ≥80% времени SLA

**Уровень 2 (Просрочка):**
- Критическое уведомление Admin'ам
- Триггер: флаг overdue = True

**Правила эскалации (настраиваемые):**
- Уровень, роль для уведомления, условие срабатывания, активность

## 4. УВЕДОМЛЕНИЯ

### 4.1. Внутренние уведомления
- Колокольчик в хедере с счётчиком непрочитанных
- Выпадающий список последних уведомлений
- Страница всех уведомлений (/notifications)
- Пометить как прочитанное / прочитать все

### 4.2. Email-уведомления
**Типы уведомлений:**
- incident_created — новый инцидент
- incident_assigned — назначение исполнителя
- status_changed — изменение статуса
- incident_resolved — инцидент решён
- incident_closed — инцидент закрыт
- new_comment — новый комментарий
- sla_overdue — просрочка SLA
- escalation — эскалация
- priority_changed — изменение приоритета
- password_changed — пароль изменён

### 4.3. Настройки уведомлений
- Для каждого типа: включить/выключить внутренние и email
- По умолчанию все включены

## 5. ДАШБОРД И СТАТИСТИКА

### 5.1. Дашборд (Manager, Admin)
**Фильтры:**
- Период: текущий месяц, прошлый месяц, квартал, год, свой период
- Отдел (только для Admin)

**Основные метрики:**
- Всего инцидентов
- Новые
- В работе
- Решённые
- Просроченные

**Графики:**
- SLA-статистика (круговая диаграмма: соблюдён/близко/просрочен)
- Распределение по статусам
- Активность за 14 дней (столбчатая диаграмма)
- Топ исполнителей за 30 дней

**Детализация (аккордеоны):**
- По исполнителям: назначено, решено, среднее время, просрочено, % SLA
- По отделам (Admin): аналогично
- SLA-аналитика: среднее время решения, распределение просрочек
- История просроченных инцидентов

### 5.2. Статистика пользователя (Manager, Admin)
- Страница /users/:id/stats
- Графики активности по дням
- Статистика по статусам
- Топ категорий
- SLA-метрики

## 7. ТЕХНИЧЕСКАЯ АРХИТЕКТУРА

### 7.1. Backend (Microservices)
```
backend/
├── api-gateway/       # Порт 8000 — маршрутизация запросов
├── services/
│   ├── user-service/      # Порт 8001 — пользователи, авторизация
│   ├── incident-service/  # Порт 8002 — инциденты, комментарии
│   ├── sla-service/       # Порт 8003 — SLA-политики, эскалация
│   └── notification-service/  # Порт 8004 — уведомления, email
└── shared/            — Общие модели, БД, Celery
```

### 7.2. Frontend
- Vue 3 + Vite
- Tailwind CSS
- Axios для API-запросов
- Pinia для состояния (auth)

### 7.3. База данных
- PostgreSQL 15
- Таблицы: users, roles, departments, incidents, statuses, priorities, categories, comments, incident_history, sla_policies, escalation_rules, notifications, notification_settings, password_reset_tokens, attachments

### 7.4. Фоновые задачи
- Celery + Redis
- check_sla_overdue — каждые 5 минут
- check_escalation — каждые 5 минут

## 8. API ENDPOINTS

### Аутентификация (/auth)
- POST /login — вход
- POST /logout — выход
- POST /refresh — обновление токена
- GET /me — текущий пользователь
- PUT /password — смена пароля
- POST /forgot-password — запрос сброса пароля
- POST /reset-password — сброс пароля по токену

### Пользователи (/users)
- GET / — список
- GET /{id} — получение
- POST / — создание
- PUT /{id} — обновление
- DELETE /{id} — удаление
- PUT /{id}/password — смена пароля (Admin)
- POST /{id}/avatar — загрузка аватара

### Отделы (/departments)
- GET / — список
- GET /{id} — получение
- POST / — создание
- PUT /{id} — обновление
- DELETE /{id} — удаление

### Инциденты (/incidents)
- GET / — список с фильтрами
- GET /{id} — получение
- POST / — создание
- POST /{id}/take — взять в работу
- POST /{id}/assign — назначить исполнителя
- POST /{id}/resolve — отметить решённым
- POST /{id}/close — закрыть
- POST /{id}/status — изменить статус
- POST /{id}/priority — изменить приоритет
- GET /{id}/history — история изменений

### Комментарии (/incidents/{id}/comments)
- GET / — список
- POST / — добавление

### SLA (/sla)
- GET /policies — список политик
- POST /policies — создание
- PUT /policies/{id} — обновление
- DELETE /policies/{id} — удаление

### Уведомления (/notifications)
- GET / — список
- POST / — создание
- POST /{id}/read — прочитать
- POST /read-all — прочитать все
- GET /settings/{user_id} — настройки
- PUT /settings/{user_id} — обновить настройки

### Отчёты (/reports)
- GET /dashboard — данные дашборда
- GET /sla-stats — SLA-статистика
- GET /status-stats — по статусам
- GET /activity — активность
- GET /executors — топ исполнителей
- GET /executors-detailed — детализация по исполнителям
- GET /departments — детализация по отделам
- GET /sla-analytics — SLA-аналитика

### Справочники
- GET /statuses — статусы
- GET /priorities — приоритеты
- GET /categories — категории
