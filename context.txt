## СИСТЕМА УПРАВЛЕНИЯ ИНЦИДЕНТАМИ (текущее описание)

### Роли
| Роль | Описание | Права |
|------|----------|-------|
| User | Пользователь | Создание инцидентов, просмотр своих, закрытие решённых |
| Executor | Исполнитель | + Взятие в работу, смена статусов, скрытые комментарии |
| Manager | Руководитель | + Назначение, просмотр всех, отчёты, история |
| Admin | Администратор | + Управление пользователями, справочниками, удаление |

### Статусы инцидента
Новый → Назначен → В работе → Решён → Закрыт

**Переходы:**
- Новый → Назначен (при назначении исполнителя)
- Новый/Назначен → В работе (при взятии в работу)
- В работе → Решён (исполнитель решил)
- Решён → Закрыт (инициатор/менеджер закрыл)

**Флаги:**
- overdue: boolean — просрочен по SLA

### Модули
1. Управление инцидентами
2. Контроль SLA
3. Многоуровневая эскалация
4. Система уведомлений (Email, внутренние)
5. Управление справочниками
6. Отчётность и аналитика
7. Профиль пользователя

### SLA-политики (рабочие часы 9:00-18:00, Пн-Пт)
- Критический: 4 часа
- Высокий: 16 часов (2 рабочих дня)
- Средний: 40 часов (5 рабочих дней / неделя)
- Низкий: 80 часов (10 рабочих дней / 2 недели)

### Эскалация
- Уровень 1: 80% времени SLA → уведомление Manager
- Уровень 2: Просрочка → уведомление Admin

## ИТЕРАЦИЯ 44: Исправление SLA-статистики (2026-04-09)

**Проблема:** Статистика SLA показывала 100% соблюдение, хотя просроченные инциденты были.

**Причины:**
1. `/reports/sla-stats` считал только `overdue=True`, игнорируя `was_overdue` для закрытых инцидентов
2. Resolve/close логика полагалась на флаг `overdue` от SLA monitor — если монитор не успел отметить, `was_overdue=False` даже при `resolved_at > sla_deadline`

**Исправления:**

1. **`/reports/sla-stats` (main.py):**
   - `overdue_count = (активные с overdue=True) + (закрытые с was_overdue=True)`
   - `on_time_count = закрытые с was_overdue=False`

2. **Resolve/close логика (incidents.py):**
   - Явная проверка `resolved_at > sla_deadline` вместо полагания на overdue флаг
   - `incident.overdue = incident.resolved_at > incident.sla_deadline`
   - `incident.was_overdue = incident.overdue`

**Для существующих данных:**
```sql
UPDATE incidents 
SET was_overdue = (resolved_at > sla_deadline OR closed_at > sla_deadline)
WHERE status_id IN (SELECT id FROM statuses WHERE name IN ('Решён', 'Закрыт'))
  AND sla_deadline IS NOT NULL
  AND was_overdue = false;
```

**Изменённые файлы:**
- `backend/services/incident-service/main.py` — `/reports/sla-stats`
- `backend/services/incident-service/routers/incidents.py` — resolve, close

**Дополнительно (та же итерация):**
- Для активных инцидентов тоже учитывается `was_overdue=True` (подтверждённое менеджером нарушение SLA)
- Формула: `overdue = активные с (overdue OR was_overdue) + закрытые с was_overdue`
- `on_time = активные без overdue/was_overdue + закрытые с was_overdue=false`
